# Multiple Photos Per Toy Design

## Overview

Allow toys to have up to 10 photos. The existing cover photo stays on the `toys` table. Additional photos are stored in a new `toy_images` table.

## Database

### New Table: `ToyImages`

| Column | Type | Nullable | Default | Notes |
|--------|------|----------|---------|-------|
| id | INT | No | Auto-increment | Primary key |
| toyId | INT | No | - | References toys.id |
| imagePath | TEXT | No | - | Full image path |
| thumbnailPath | TEXT | Yes | - | Generated thumbnail |
| sortOrder | INT | No | 0 | Display order |
| createdAt | DATETIME | No | Now | Auto-set |

Schema version bumps from 2 to 3. Migration creates the new table. No existing data migration needed — the `toys.imagePath` remains the cover photo.

### New Database Methods

- `getImagesForToy(int toyId)` — returns `List<ToyImage>` ordered by `sortOrder`
- `insertToyImage(ToyImagesCompanion)` — inserts and returns the new id
- `deleteToyImage(int id)` — deletes a single image row
- `deleteImagesForToy(int toyId)` — deletes all images for a toy (used when deleting the toy)
- `countImagesForToy(int toyId)` — returns count for enforcing the 10-image limit

## Provider

New `toyImagesProvider` — a `FutureProvider.family<List<ToyImage>, int>` keyed on toyId. Fetches images from the `toy_images` table via `getImagesForToy()`.

The 10-image limit is enforced in the provider/UI layer: check count before allowing the add button, show "10 of 10" indicator.

## Detail Screen Changes

### Photo Gallery

Below the existing cover image (which stays as-is), add a horizontal scrollable thumbnail strip:

- Shows the cover photo as the first thumbnail (pulled from `toy.thumbnailPath ?? toy.imagePath`)
- Followed by additional photos from `toy_images` in sort order
- Tapping a thumbnail swaps it into the main image view above
- A "+" button at the end of the strip opens camera/gallery picker (reuses the same `ImagePicker` logic from capture screen)
- Long-press a thumbnail (not the cover) to show a delete confirmation dialog
- The strip is hidden when there are no additional photos and the cover image is empty

### Adding Photos

Uses the existing `ImageStorageService.saveImage()` for storage and thumbnail generation. After saving, inserts a row into `toy_images` with the next `sortOrder` value.

### Deleting Photos

Calls `ImageStorageService.deleteImage()` to remove files, then `deleteToyImage()` to remove the DB row. Cover photo deletion is not supported here — it stays tied to the toy record.

### Deleting a Toy

The existing `deleteToy()` in `InventoryNotifier` must also call `deleteImagesForToy()` to clean up additional images and their files.
